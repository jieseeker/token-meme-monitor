# 极简视图与专业指标双视图方案

日期：2026-10-26  
状态：已实现（本地待验收）  
目标实现者：后续 GPT / 开发代理

## 1. 背景与问题

当前项目是代币发现与监控面板，只做研究和展示，不做站内下单或账户交易。页面已经包含较完整的交易者视角数据：

- 结构阶段：A/B/C、观察、启动、回调、企稳等。
- 结构因子：30m 突破、相对成交量、买压、5m/15m 动量、流动性稳定。
- 市场数据：价格、涨跌、成交额、池内资产、OI、深度、大额交易、链上转账。
- 数据状态：预热、连续、断档、风险通过/警告/阻断。

主要问题不是数据缺失，而是信息层级对新手不友好：

1. 页面指标多，新手不知道优先看什么。
2. 活跃度分和结构因子容易被理解成“可以买”，但系统本意是“值得观察”。
3. 强趋势币在首次确认失败后可能大幅拉升，原 B 买点已经失效；如果仍显示“等待量能确认”，用户会误解为还有基础买点。
4. 新手最需要先看到的是：数据是否可用、风险是否阻断、当前位置是否适合、错了在哪里退出。

典型案例 DOOD：

- B 观察线约 `0.001418`。
- 首次突破时 1h 量能未达到确认条件。
- 后续价格拉升到约 `0.002027`，高出 B 线约 42%。
- 原逻辑显示“B 候选 / 等待量能确认”，容易误导。
- 已在提交 `8321ed3` 中增加“B 超出确认窗 / 等待回踩后重新突破”文案。

后续需要在“专业指标”外增加一层面向新手的极简决策视图。

## 2. 目标

做一个双层信息架构：

1. **极简视图**：默认给新手，只回答五个问题：
   - 现在能不能看？
   - 现在是不是买点，还是已经涨远？
   - 风险能不能接受？
   - 买错了在哪里退出？
   - 新手应该采取什么保守动作？
2. **专业视图**：保留现有全部指标和页面布局，服务有经验的交易者。

两个视图不是两套业务逻辑，而是同一份前端数据的不同呈现层。

## 3. 非目标

第一阶段不要做以下事情：

- 不新增后端接口。
- 不改信号引擎和结构状态机。
- 不提供买入、卖出、仓位计算或收益承诺。
- 不把“绿色”表达为可以买，只表达为进入观察区。
- 不删除任何现有专业指标。
- 不大幅重排现有页面，避免把已经可用的高级视图改乱。

## 4. 用户与场景

### 新手用户

- 看不懂 B/C/E、OI、深度、相对成交量。
- 只需要一个保守结论和明确风险。
- 容易被涨幅、分数、强趋势吸引而追高。
- 需要“已涨远，不追”“风险阻断，不碰”“数据过期，先等”这类直接反馈。

### 专业用户

- 需要查看完整结构因子、OI、深度、大额交易、链上数据。
- 希望保留现有页面密度和更新时间。
- 可接受手动切换到专业视图。

## 5. 信息架构

详情页顶部增加一个视图切换：

```text
[极简] [专业]
```

- 第一次打开默认 `极简`。
- 用户点击后写入 `localStorage`。
- 推荐键名：`tmm-view-mode-v1`，取值 `simple` / `pro`。
- 刷新后保持用户选择。

### 极简视图结构

```text
┌────────────────────────────────────────────┐
│ 极简决策卡                                  │
│                                            │
│ 状态：已涨远，不建议新手追                    │
│ 原因：价格高于 B 线 42% · 首次量能未确认        │
│                                            │
│ 位置：已超过 +8% 确认窗                       │
│ [回踩区] [确认区] [已涨远]                    │
│                                            │
│ 风险：通过 · 流动性 $202K · 数据 32秒前         │
│ 失效：跌破 B 线 / 流动性下降 / 买压消失          │
│                                            │
│ 建议：等待回踩，不追高                         │
└────────────────────────────────────────────┘
```

极简视图下，下方专业区可以先整体弱化或隐藏，但不要删除 DOM 中依赖的容器和逻辑。推荐做法：

- 详情页只渲染极简卡 + 一个“查看专业指标”按钮。
- 切到专业视图后再渲染现有完整详情。
- 避免同一屏同时展示两套结论造成拥挤。

### 专业视图结构

保留当前详情页：

- 第一卡片：交易摘要、基础行情、大额净流入。
- 结构阶段与六因子。
- OI、市场价格对比、深度、大额交易、链上转账。
- 每个模块继续显示自己的更新时间。

专业视图可以基本复用现有实现，只调整外层容器和切换逻辑。

## 6. 左侧列表优化

极简视图下，左侧每个代币只显示一个很短的状态词，避免复杂数据撑高卡片：

```text
DOOD    已涨远
IN      等待买点
ORDER   接近买点
XXX     不碰
```

专业视图下可以保留当前结构阶段和快照年龄。

不要在左侧列表直接堆结构因子、风险详情或更新时间，这些放到 tooltip 或详情页。

## 7. 极简状态设计

先在前端实现纯函数，例如：

```javascript
noviceState(token, structure)
```

输入现有 `/api/tokens`、`/api/token/{token}/summary`、`/api/structure` 数据，输出：

```javascript
{
  key: "too_far",
  label: "已涨远",
  action: "不追高",
  tone: "warning",
  reason: "价格高于 B 线 42%",
  invalidations: ["跌破 B 线", "流动性下降", "买压消失"]
}
```

### 第一版状态矩阵

| key | 显示状态 | 触发条件 | 建议动作 | 色调 |
|---|---|---|---|---|
| `data_stale` | 数据过期 | 行情或结构数据超过新鲜度阈值 | 先等更新，不做判断 | 灰 |
| `risk_block` | 不碰 | `risk_status=BLOCK`，或流动性/深度异常 | 不参与 | 红 |
| `too_far` | 已涨远 | 有 B 线，价格高于 B 线 8% 以上，且 B 未确认 | 等回踩，不追高 | 橙/黄 |
| `wait_volume` | 等待量能 | B 已突破但量能未确认，价格仍在确认窗内 | 继续观察 | 黄 |
| `near_buy` | 接近买点 | 价格接近 B 线或有效回踩支撑 | 进入观察区 | 绿 |
| `wait_setup` | 等待买点 | 尚无有效 B/支撑结构 | 等待结构形成 | 灰/蓝 |
| `unknown` | 信息不足 | 关键数据缺失或状态未知 | 不判断 | 灰 |

注意：

- `risk_block` 和 `data_stale` 的优先级高于其他状态。
- `near_buy` 不等于买入建议，只表示进入观察区。
- 未知必须显示未知，不能默认风险通过。

## 8. 买点距离轴

这是极简视图的核心组件。

当 `structure.b_breakout_line` 存在且价格有效时：

```javascript
distance = price / b_breakout_line - 1
```

建议分带：

| 区间 | 含义 | 展示 |
|---|---|---|
| `< -5%` | 还没接近 | 等待买点 |
| `-5% ~ 0%` | 接近 B 线 | 接近观察区 |
| `0% ~ +8%` | 突破确认窗 | 等待量能或确认 |
| `> +8%` | 已脱离基础买点 | 已涨远，不追 |

展示要求：

- 用一条横向位置轴，不要用复杂数字表。
- 当前价格位置用圆点。
- B 线和 +8% 上限清楚标出。
- 数值只保留一个百分比，例如 `+42%`。
- 无 B 线时显示“等待结构形成”，不要造假轴线。

## 9. 数据新鲜度规则

第一版先使用保守阈值：

| 数据 | 新鲜阈值 | 超过后展示 |
|---|---:|---|
| 行情快照 | 120 秒 | `行情过期` |
| 结构因子 | 180 秒 | `结构过期` |
| OI | 2 小时 | `OI 样本过期`，但 OI 不应阻断整体行情 |
| 深度 | 10 分钟 | `深度过期` |
| 大额交易 | 10 分钟 | `大额数据过期` |

极简卡顶部显示统一摘要：

- `数据 32秒前`
- `行情过期 3分钟`
- `结构过期 5分钟`

过期时：

- 卡片降低透明度或加灰色边框。
- 状态优先显示 `数据过期`。
- 不显示得像实时数据。

## 10. 风险展示

极简卡只显示风险结论和最关键证据：

```text
风险：阻断 · 流动性极低
风险：通过 · 流动性 $202K
风险：未知 · 深度未刷新
```

第一版至少使用：

- `structure.risk_status`
- `signal_risk_flags`
- `liquidity_usd`
- 数据新鲜度

后续可以补充：

- 买入/卖出冲击成本。
- 卖出限制、税率、持仓集中度。
- 是否只有单池、单交易所。

在完整安全数据未接入前，不要宣称“安全”，只能显示“当前规则未命中”或“未知”。

## 11. 失效条件

极简卡必须展示“什么情况说明判断错了”。

第一版按结构阶段映射：

| 状态 | 失效条件 |
|---|---|
| 等待买点 | 数据断档或结构失效 |
| 等待量能 | 突破失败或量能不足 |
| 已涨远 | 跌破观察线或确认失败 |
| 接近买点 | 跌破观察线 / 支撑 |
| 强趋势 | 买压消失、流动性下降、15m 动量转负 |

文案必须具体，不要只写“趋势破坏”。

## 12. 强趋势延续状态

第一版可以先不做 `E 强趋势延续`，但设计上预留。

候选条件：

- 价格高于 B 线 8% 以上。
- 1h 量能 ≥ 基线 2 倍且 ≥ `$15K`。
- 15m 动量 > 2%。
- 买压 ≥ 50%。
- 流动性稳定 ≥ 0.98。
- 风险不是 `BLOCK`。

显示：

```text
强趋势延续 · 已脱离基础买点
只观察延续，不当作 B 点追高
触发：5m 缩量回踩不破趋势线
失效：买压消失、流动性下降或 15m 动量转负
```

对新手默认动作仍是保守的：

- 不建议追高。
- 只做观察或等待回踩。
- 不能因强趋势而隐藏风险。

## 13. 视觉设计要求

- 复用现有 CSS 变量和设计体系，不引入新颜色系统。
- 极简卡要比专业卡片更少边框、更少数字。
- 主状态字号最大，其次是原因、位置轴、风险、失效条件。
- 色彩只用于状态，不用来装饰。
- 移动端极简卡必须单列展示，位置轴可横向滚动但不允许整页横向滚动。
- 视图切换按钮必须有清晰 `aria-pressed`。
- 不使用闪烁、弹窗、强提醒打断用户。

## 15. 测试与验收

### 单元检查

在 `detail.test.cjs` 增加：

1. 默认视图为极简。
2. 切换到专业后写入 localStorage。
3. `risk_block` 优先于 `too_far`。
4. `data_stale` 优先于 `near_buy`。
5. 有 B 线且价格高于 B 线 8% 时显示 `已涨远`。
6. 无 B 线时显示 `等待结构形成`，不渲染假轴线。
7. 未知风险必须显示未知，不能显示通过。
8. 极简卡包含状态、原因、风险、失效条件和建议动作。
9. 专业视图仍包含结构阶段、六因子、OI、深度、大额交易。

### 人工验收

1. 桌面端无整页横向滚动。
2. 375px 宽度下极简卡可读。
3. 切换极简/专业后刷新，偏好保留。
4. DOOD 应显示“已涨远，不追高”，不是“等待量能确认”。
5. 数据过期时页面明显降级，不能看起来仍实时。
6. 左侧列表极简状态不超过 4 个中文字符或同等宽度。

## 16. 给实现者的开发提示

请按最小可用版本实现：

1. 先加视图模式和极简卡。
2. 再加左侧极简状态。
3. 再加买点距离轴。
4. 最后才考虑强趋势延续状态。

不要一次性重构整个详情页。第一版验收标准是新手能一眼看懂“能不能看、是不是买点、风险如何、哪里退出”，专业视图完整无损。
